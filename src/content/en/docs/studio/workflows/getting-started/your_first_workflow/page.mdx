# Your first workflow

This guide walks you through creating a workflow that executes a single activity and triggers it from the Mistral Console or the local project tooling.

<SectionTab as="h2" sectionId="prerequisites">Prerequisites</SectionTab>

To complete this quickstart, you need:

- A [Mistral account](https://console.mistral.ai/)
- [Python](https://www.python.org/downloads/) 3.12 or later
- [uv](https://docs.astral.sh/uv/getting-started/installation/) installed in your environment (`uvx` ships with `uv`)

<SectionTab as="h2" sectionId="step-1">Step 1: Scaffold your project</SectionTab>

Run the following command in your terminal:

```bash
uvx mistralai-workflows-cli setup
```

The CLI scaffolds a ready-to-run Python project with the Workflows SDK already configured, a minimal example workflow, and helper commands to run your worker and trigger executions.

The command prompts you to generate a [Mistral API key in the Mistral Console](https://console.mistral.ai/home?profile_dialog=api-keys). Enter the key when asked. API keys are shown only once.

Open the generated project directory in your editor. The default folder name is `my-workflow` unless you chose a different name during setup.

<SectionTab as="h2" sectionId="step-2">Step 2: Understand the workflow</SectionTab>

Open `src/workflows/hello.py`. The scaffolded project includes a minimal example like this:

```python
from pydantic import BaseModel
import mistralai.workflows as workflows


class HelloInput(BaseModel):
    name: str = "World"


@workflows.activity()
async def greet(name: str) -> str:
    return f"Hello, {name}! Welcome to Mistral Workflows."


@workflows.workflow.define(
    name="hello-world",
    workflow_display_name="Hello World",
    workflow_description="A minimal hello-world workflow.",
)
class HelloWorkflow:
    @workflows.workflow.entrypoint
    async def run(self, input: HelloInput) -> str:
        return await greet(input.name)
```

Two things to notice:

- `@workflows.activity()` marks a function as a durable step. If the process crashes mid-run, the platform replays from the last completed activity.
- `@workflows.workflow.define` registers the workflow with a name you use to trigger it.

<SectionTab as="h2" sectionId="step-3">Step 3: Start the worker</SectionTab>

From the root of your project, run:

```bash
make start-worker
```

You can also start the examples workflows with:

```bash
make start-examples
```

The worker connects to the Mistral API, registers your workflow, and waits for tasks. Keep this terminal open.

<SectionTab as="h2" sectionId="step-4">Step 4: Trigger the workflow</SectionTab>

With the worker running, open a second terminal and trigger an execution using the Makefile command:

```bash
make execute workflow=hello-world input='{"name": "World"}'
```

You can also trigger it from the [Mistral Console](https://console.mistral.ai/):

1. Open **Workflows** in the sidebar.
1. Select **hello-world**.
1. Click **Start Workflow** and pass `{"name": "World"}` as the input.
1. Open the **Executions** tab to watch it run.

<SectionTab as="h2" sectionId="verify">Verify</SectionTab>

The workflow completes with the following output:

```json
{
  "result": "Hello, World! Welcome to Mistral Workflows."
}
```

If the worker terminal shows a connection error, confirm that your API key is set correctly and that the worker process is still running.

Press `Ctrl+C` to stop the worker when you are done.
